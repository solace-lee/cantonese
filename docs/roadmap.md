# Canto芽开发计划与换机交接

本文记录 2026-11-12 的项目状态、已确定的产品方向和后续开发计划。任务复选框表示规划，勾选前应重新检查代码并完成对应验证。

## 产品方向

- 面向儿童的 AI 粤语学习网站，提供自由对话、卡通角色、适龄交互和随对话变化的场景。
- 默认纯前端静态部署，家长自行配置兼容接口和 API Key（BYOK）。不要求服务端管理对话资源；`server/` 是可选的本地用户服务示例，不是生产认证系统。
- 渲染方案已确定为 **SVG 角色和场景 + Canvas 2D 特效**。模型只返回受约束的场景数据，前端校验后使用白名单组件渲染，不直接注入模型生成的 SVG 或 HTML。
- 支持 3–6 岁、6–12 岁等不同年龄段；电视使用首先以电脑连接大屏、使用鼠标键盘为目标，遥控器支持作为后续扩展。
- 项目计划开源，许可证尚待确定。

## 当前状态

- 已有 OpenAI 兼容接口配置、文字多轮对话和按年龄段切换的提示词。对话只保存在当前页面内存，请求最多携带最近 20 条消息。
- 已有四个内置主题、场景 JSON 校验、SVG 渲染、缓存和失败回退。当前场景生成只接收主题名称，没有具体对话情节；同一主题下不同故事不一定呈现不同画面。
- 已有浏览器语音播放和卡通嘴型，但嘴型只是固定节奏的近似动画，并非发音同步；`zh-HK` 音色取决于设备。尚无语音识别或跟读评分。
- 已有大屏布局切换；尚未完成电视真实设备、遥控器及完整键盘体验验证。
- 已移除虚构用户、学习统计和未实现的导航入口；目前没有学习统计、页面登录或偏好同步功能。
- 模型配置目前保存在浏览器 `localStorage`，生成场景缓存在 IndexedDB。清空对话与场景的按钮不会清除模型配置或 API Key。
- 上一次开发中生产构建及 5 项核心测试通过；浏览器界面检查未完成，尚未使用真实模型接口完成端到端验证。此处是历史结果，换机后需要重新验证。

## 换机继续开发

1. 确认本文件等需要带走的修改已经复制到新机器，或在当前机器自行提交并推送后再克隆。未提交的本地文件不会随远端仓库自动迁移；不要提交 API Key、儿童对话或本机浏览器数据。
2. 安装 Node.js 和 npm。当前 Vite 依赖要求 Node.js `^20.19.0 || >=22.12.0`；本次检查环境为 Node.js `v26.6.0`、npm `11.18.0`。新机器建议使用满足要求的受支持版本。
3. 在项目根目录执行：

   ```bash
   npm ci
   npm run dev
   ```

   按终端显示的本地地址打开网站。在“配置”中重新填写 Base URL、模型和 API Key。自定义服务可使用无密钥代理；浏览器直连需要服务商允许 CORS。
4. 执行 `npm test` 和 `npm run build`，确认新环境正常。`node_modules` 不需要迁移，使用锁文件重新安装即可。
5. 模型配置、年龄和大屏偏好、场景缓存都属于当前浏览器数据，不随代码仓库迁移；对话只存在页面内存。新机器需重新配置，不要通过提交配置文件传播密钥。

更多接口说明见 [providers.md](./providers.md)，可选服务端边界见 [server/README.md](../server/README.md)。

## P0：稳定现有使用流程

- [ ] 增加模型连接测试，并区分配置错误、鉴权失败、跨域、网络错误和超时；避免暴露密钥或敏感服务响应。
- [ ] 为对话增加超时、取消和可重试机制；请求失败保留输入，清除或切换配置时防止旧请求覆盖新状态。
- [ ] 增加不保存 API Key 的选项和清除配置入口；向家长说明所选服务会接收对话，提示纯前端无法保护共享密钥。
- [ ] 合并重复的年龄段配置，明确 6 岁属于哪个分组，并让提示词与界面交互使用同一配置来源。
- [ ] 增加关键流程的浏览器测试：配置、发送、失败恢复、切换年龄、缓存与配置清理；用实际模型服务进行一次端到端联调。

**验收：**配置可用接口后能完成多轮文字对话；失败可理解、可重试；用户可选择不保存或清除本机密钥，切换配置后旧请求不会污染新会话。

## P1：让场景反映对话情节

- [ ] 从对话提取受约束的场景摘要，传给场景生成请求；考虑隐私，避免把儿童原话或个人信息直接写入缓存键。
- [ ] 保留白名单与输入校验，扩充动物、玩具、环境元素及可控的角色动作、表情和元素层级。
- [ ] 按规范化场景语义调整缓存键，并增加缓存数量限制、版本迁移和清理策略。
- [ ] 处理场景请求的先后顺序，确保用户手动切换后，旧对话或旧场景响应不会覆盖新的选择。
- [ ] 测试非法模型输出、超时、缓存失效和回退，并用真实模型检验不同情节的画面差异。

**验收：**同一池塘主题下，“小鸭在游泳”和“玩具球在岸边”能产生明显不同的画面；生成失败时回退内置场景，模型返回内容不能作为原始 SVG/HTML 注入。

## P2：粤语语音与口型同步

- [ ] 调研并抽象可配置的粤语语音合成接口；浏览器语音保留为能力可用时的备选。
- [ ] 选择能提供音素、viseme 或其他可靠时间标记的语音能力，将标记映射到角色嘴型；对不能提供标记的服务明确使用近似动画。
- [ ] 加入粤语语音输入：开始录音、结束、识别结果、确认或发送，以及权限和失败处理。
- [ ] 评估实际设备上的粤语识别、合成发音和口型时间对应效果；跟读纠音及评分待有可靠识别能力后再设计。
- [ ] 核实服务商浏览器接入、费用、数据处理和设备兼容性，保留服务不可用时的替代流程。

**验收：**在选定服务与目标设备上可通过语音发起对话；支持时间标记的语音播放能据此驱动嘴型，并有可复现的人工验证样例。

## P3：儿童体验与大屏

- [ ] 3–6 岁：增加图卡、较少的选择和动作引导，保留家长代操作方式。
- [ ] 6–12 岁：完善开放提问、粤拼、场景任务和适量解释；验证两个年龄段的文案与交互区别。
- [ ] 完善个人信息提醒、适龄内容处理与家长说明；提示词不是完整的内容安全保障，需要使用具体样例评估。
- [ ] 以电脑连接电视为首批场景，验证远距离字号、键盘焦点、布局和鼠标操作；如需要电视遥控器，再实现方向键、确认和返回。
- [ ] 在实际电脑、手机和目标大屏设备上检查浏览器、音频、麦克风权限与网络兼容性。

**验收：**两个年龄段具有可观察的交互差别；在目标大屏环境可看清内容并完成一次对话。

## P4：开源发布准备

- [ ] 由项目所有者确定许可证，补充贡献、部署和问题反馈说明。
- [ ] 配置自动构建与测试，记录浏览器、真实接口和目标设备的验证结果。
- [ ] 审查依赖、构建产物与忽略规则；检查外部字体等资源在不同网络环境的可用性。
- [ ] 再次核对隐私说明、API Key 处理和可选服务端的能力边界；不把本地用户服务示例作为生产认证方案。
